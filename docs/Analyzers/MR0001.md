# MR0001: A task becomes the value of a result

| Property | Value |
| -------- | ----- |
| **Rule ID** | MR0001 |
| **Title** | A task becomes the value of a result |
| **Category** | Usage |
| **Severity** | Error |
| **Code fix** | Yes, for `Then` and `Result.Try` |

## Cause
A function passed to a method of the library returns a `Task`, a `Task<T>`, a `ValueTask` or a `ValueTask<T>`, and the compiler inferred that type as the type of the value of the result that the method returns; or the call returns a task of a task.

## Rule description
The method stores what the function returns as the value of the result. A task stored this way is never awaited: `result.Then(x => GetAsync(x))` is a `Result<Task<int>>`, which is successful before the task completes and also when the task fails.

The rule is about tasks only. A `Result`, a `Result<T>` or an `Error` that a function returns never becomes a value this way: the methods have overloads that flatten them.

The rule reports:

* a function that returns a task in `Then` or `Result.Try`, which do not await it;
* a function that returns a `Task` or a `ValueTask` without a value in `ThenAsync` on a task of a result (e.g., `task.ThenAsync(x => SaveAsync(x))`), which awaits the task of a result, but has no result to continue with;
* a `select` clause of a query that returns a task (the `Select` and `SelectMany` methods);
* two functions that return a task passed to `MatchAsync` as `ifSuccessFunction` and `ifErrorFunction`: the call binds to the overload with two synchronous functions and returns a task of a task.

The rule does not report a task that is kept on purpose:

* a call that names its type arguments (e.g., `result.Then<int, Task<int>>(…)`);
* `Result.FromValue`, and a function that returns the result itself (e.g., `x => Result.FromValue(GetAsync(x))`);
* a call on a result that already holds a task (e.g., `resultOfTask.IfSuccess(…)`): the type of its value was chosen before the call;
* `Match` with two functions that return a task: it returns the task of the function that ran, which the caller awaits.

## How to fix violations
* In `Then` and `Result.Try`, use `ThenAsync` and `Result.TryAsync`, and await the call. For a function that returns a task without a value, use `IfSuccessAsync` instead of `Then`: `ThenAsync` takes no such function. The code fix renames the method accordingly and awaits the call where that is possible (see [Code fixes](README.md#code-fixes)).
* In `ThenAsync` on a task of a result, use `IfSuccessAsync` for a function that returns a task without a value: it awaits the task and returns the result unchanged.
* In a query, chain the operation in a `from` clause whose function returns a `Task<Result<T>>` or a `ValueTask<Result<T>>`, or use `ThenAsync`.
* In `MatchAsync`, pass the two functions without names, or as `ifSuccessAction` and `ifErrorAction`: they are awaited.
* To keep the task in the result on purpose, name the type arguments or wrap the task with `Result.FromValue`.

## When to suppress
This rule cannot be suppressed by the usual means, as a compile error cannot: see [Configuring the rules](README.md#configuring-the-rules). A task that is meant to be the value of the result is written with explicit type arguments or with `Result.FromValue`, and is then not reported.

## Examples
### Violations
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Task<int> GetIntAsync() => Task.FromResult(5);
Task SaveAsync() => Task.CompletedTask;
Error MapException(Exception e) => Error.Failure(ErrorUri.None, "The operation failed.");

// MR0001: a Result<Task<int>>, whose task nobody awaits
var wrapped = ok.Then(x => GetIntAsync());

// MR0001: a Result<Task<int>>; Try does not await the task
var tried = Result.Try(() => GetIntAsync(), MapException);

// MR0001: a Task<Result<Task>>
var saved = okTask.ThenAsync(x => SaveAsync());

// MR0001: a Result<Task<int>>
var selected = from x in ok select GetIntAsync();

// MR0001: a Task<Task>
var matched = okTask.MatchAsync(ifSuccessFunction: x => SaveAsync(), ifErrorFunction: e => SaveAsync());
```

### Fixes
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Task<int> GetIntAsync() => Task.FromResult(5);
Task<Result<int>> GetResultAsync() => Task.FromResult(ok);
Task SaveAsync() => Task.CompletedTask;
Error MapException(Exception e) => Error.Failure(ErrorUri.None, "The operation failed.");

Result<int> next = await ok.ThenAsync(x => GetIntAsync());

Result<int> tried = await Result.TryAsync(() => GetIntAsync(), MapException);

Result<int> saved = await okTask.IfSuccessAsync(x => SaveAsync());

Result<int> selected = await (from x in ok from y in GetResultAsync() select y);

await okTask.MatchAsync(x => SaveAsync(), e => SaveAsync());
```

### A task kept on purpose
```csharp
Result<int> ok = Result.FromValue(1);
Task<int> GetIntAsync() => Task.FromResult(5);
Error MapException(Exception e) => Error.Failure(ErrorUri.None, "The operation failed.");

// Not reported: the type arguments are named
Result<Task<int>> named = ok.Then<int, Task<int>>(x => GetIntAsync());
Result<Task<int>> tried = Result.Try<Task<int>>(() => GetIntAsync(), MapException);

// Not reported: the function returns the result itself
Result<Task<int>> returned = ok.Then(x => Result.FromValue(GetIntAsync()));
Result<Task<int>> selected = from x in ok select Result.FromValue(GetIntAsync());

// Not reported: Result.FromValue
Result<Task<int>> created = Result.FromValue(GetIntAsync());
```
