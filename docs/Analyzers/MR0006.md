# MR0006: A result is discarded

| Property | Value |
| -------- | ----- |
| **Rule ID** | MR0006 |
| **Title** | A result is discarded |
| **Category** | Usage |
| **Enabled by default** | As warning |
| **Applicable languages** | C# |
| **Code fix** | Yes |

## Cause
A statement is a call that returns a `Result`, a `Result<T>`, an `IOperationResult`, or a `Task` or a `ValueTask` of one, and nothing uses what the call returns. The call can be awaited, also with `ConfigureAwait` (e.g., `await SaveAsync(order).ConfigureAwait(false);`), and it can follow a null-conditional access (e.g., `order?.Save();`). A statement that awaits a variable is reported too (e.g., `await saving;`, where `saving` is a `Task<Result>`).

## Rule description
A result says whether the operation failed only to the code that looks at it. A statement such as `await SaveAsync(order);`, where `SaveAsync` returns a `Task<Result>`, drops a failed result, and the code continues as if the order was saved.

A task of a result that is not awaited at all (e.g., `SaveAsync(order);` in a method that is not `async`) is reported with a message of its own: the task runs without anyone waiting for it, and its result and any exception are lost.

The rule looks at the calls of every method, not only of the methods of the library. It also reports the body of a lambda passed to a method that is not of the library (e.g., `ids.ForEach(id => repository.Delete(id))`), and a statement in the block body of a lambda passed to a method of the library (e.g., `result.IfSuccess(x => { Validate(x); })`). For the expression body of a function passed to a method of the library, see [MR0004](MR0004.md).

A statement that ends with `Then`, `Else` or one of their asynchronous forms is reported too: these methods return a new result whose error nobody has seen yet. So is a statement that ends with `IfSuccess` or `IfSuccessAsync` when their result comes from a call (e.g., `Load().IfSuccess(x => Show(x));`): they return the result that they were given, which is then lost.

The rule does not report:

* a discard (e.g., `_ = Save();`);
* any use of the value: an assignment, an argument, a `return`, a member access (e.g., `Save().IsSuccess`);
* a statement that ends with `IfError`, `IfErrorAsync`, `Match` or `MatchAsync` of the library, which handled the error;
* `IfSuccess` or `IfSuccessAsync` on a result that is stored in a variable, a field or a property (e.g., `result.IfSuccess(x => Show(x));`): the method returns that result, so nothing is lost;
* `Switch` and `SwitchAsync`, which return no result.

## How to fix violations
* Check the result (e.g., `IsError`, `TryGetError`), return it, or handle its error with `IfError` or `Match`.
* To ignore the result on purpose, discard it: `_ = Save();`. The code fix adds the discard.
* For a task of a result that is not awaited, await it and check the result. To ignore the result on purpose, await the task and discard the result: `_ = await SaveAsync(order);`. The code fix does that in an `async` method, local function or lambda and in top-level statements, where an `await` is allowed, and offers nothing elsewhere: a discarded task (`_ = SaveAsync(order);`) would hide the task as well as the failure. An `await` is not allowed inside a `lock`, `unsafe` or `fixed` statement, in an unsafe member or type, in a query or in a catch filter. After a null-conditional access (`repository?.SaveAsync(order);`) no fix is offered either: the task is `null` when the receiver is, and awaiting it would throw where the call did nothing.

## When to suppress warnings
Suppress a warning of this rule when a failure of the call does not matter; a discard says the same without a suppression.

## Suppress a warning
To suppress one violation, disable the rule before the line and restore it after the line.

```csharp
#pragma warning disable MR0006
// The line that the rule reports.
#pragma warning restore MR0006
```

To switch the rule off for a file, a folder or a project, set its severity to `none` in a [configuration file](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/configuration-files) (e.g., `.editorconfig`).

```ini
[*.cs]
dotnet_diagnostic.MR0006.severity = none
```

For more information, see [Configuring the rules](README.md#configuring-the-rules) and [How to suppress code analysis warnings](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/suppress-warnings).

## Examples
### Violations
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Result Save() => Result.Success();
Result<int> Load() => 1;
Task<Result> SaveResultAsync() => Task.FromResult(Result.Success());

// MR0006: a failure is lost
Save();
await SaveResultAsync();

// MR0006: the task of the result is neither awaited nor used
SaveResultAsync();

// MR0006: what the await gives is not used
await SaveResultAsync().ConfigureAwait(false);

// MR0006: the results that these methods return are not used
ok.Then(x => x + 1);
ok.IfSuccess(x => Console.WriteLine(x));
await okTask.ThenAsync(x => x + 1);

// MR0006: the body of a lambda passed to a method that is not of the library
new List<int> { 1 }.ForEach(x => Load());

// MR0006: a statement in the block body of a lambda passed to a method of the library
ok.IfSuccess(x => { Save(); });
```

### Fixes
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Result Save() => Result.Success();
Result<int> Load() => 1;
Task<Result> SaveResultAsync() => Task.FromResult(Result.Success());
void Log(Error e) { }

// The result is used
var saved = Save();
var isSaved = Save().IsSuccess;
Console.WriteLine(Load());

// The error is handled
ok.IfError(e => Log(e));
ok.Then(x => x + 1).IfError(e => Log(e));
await okTask.IfErrorAsync(e => Log(e));
ok.Switch(x => Console.WriteLine(x), e => Log(e));

// The result is discarded on purpose
_ = Save();
_ = await SaveResultAsync();
_ = await SaveResultAsync().ConfigureAwait(false);
```
