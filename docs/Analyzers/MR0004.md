# MR0004: A side effect method drops the result of its function

| Property | Value |
| -------- | ----- |
| **Rule ID** | MR0004 |
| **Title** | A side effect method drops the result of its function |
| **Category** | Usage |
| **Enabled by default** | As error; [not configurable](README.md#configuring-the-rules) |
| **Applicable languages** | C# |
| **Code fix** | Yes, for `IfSuccess` and `IfSuccessAsync`; for `IfError` and `IfErrorAsync` when the function returns an `Error` or the type of the result itself |

## Cause
A function passed to `IfSuccess`, `IfError`, `Switch` or one of their asynchronous forms returns a `Result`, a `Result<T>` or an `Error`, or a task of one where the method awaits a task without a value.

## Rule description
`IfSuccess`, `IfError`, `Switch`, `IfSuccessAsync`, `IfErrorAsync` and `SwitchAsync` run a function for its side effect and ignore what it returns. A function that returns a result or an `Error` is therefore never checked: `result.IfSuccess(x => Validate(x))` returns the original, successful result also when `Validate` fails.

The rule reports a lambda with an expression body and a method group (e.g., `result.IfSuccessAsync(ValidateAsync)`).

The rule does not report:

* an assignment, whose value is stored (e.g., `x => last = Validate(x)`);
* a lambda with a block body (e.g., `x => { Validate(x); }`);
* a function that returns anything else (e.g., `x => Console.WriteLine(x)`).

## How to fix violations
* In `IfSuccess` and `IfSuccessAsync`, use `Then` and `ThenAsync` to continue with the result of the function: a failed one makes the chain fail. The code fix renames the method.
* In `IfError` and `IfErrorAsync`, use `Else` and `ElseAsync` to replace the failed result with the result of the function, or handle the returned result inside the function. The code fix renames the method when the function returns an `Error` or the type of the result itself, which is what `Else` takes.
* In `Switch` and `SwitchAsync`, handle the returned result inside the function.

## When to suppress warnings
Do not suppress this rule. To ignore the result of the function on purpose, discard it in a block body (e.g., `x => { _ = Validate(x); }`), which is not reported.

## Suppress a warning
The rule is reported as an error and is not configurable: `#pragma warning disable MR0004`, `<NoWarn>` in the project file and a severity in a configuration file have no effect, as for a compile error. See [Configuring the rules](README.md#configuring-the-rules) for what still silences it.

## Examples
### Violations
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Result<int> Validate(int x) => x;
Task<Result<int>> ValidateAsync(int x) => Task.FromResult(Result.FromValue(x));
Result Audit(Error e) => Result.Success();
void Log(Error e) { }

// MR0004: a failure of Validate is lost
_ = ok.IfSuccess(x => Validate(x));
_ = okTask.IfSuccessAsync(x => Validate(x));

// MR0004: the task is awaited, and its Result<int> is ignored
_ = ok.IfSuccessAsync(x => ValidateAsync(x));
_ = ok.IfSuccessAsync(ValidateAsync);

// MR0004: a failure of Audit is lost
_ = ok.IfError(e => Audit(e));
ok.Switch(x => Validate(x), e => Log(e));
```

### Fixes
```csharp
Result<int> ok = Result.FromValue(1);
Task<Result<int>> okTask = Task.FromResult(ok);
Result<int>? last = null;
Result<int> Validate(int x) => x;
Task<Result<int>> ValidateAsync(int x) => Task.FromResult(Result.FromValue(x));

Result<int> validated = ok.Then(x => Validate(x));
Result<int> validatedLater = await okTask.ThenAsync(x => Validate(x));
Result<int> validatedAsync = await ok.ThenAsync(x => ValidateAsync(x));

// Not reported: the result is stored
_ = ok.IfSuccess(x => last = Validate(x));

// Not reported: the result is ignored on purpose
_ = ok.IfSuccess(x => { _ = Validate(x); });
```
