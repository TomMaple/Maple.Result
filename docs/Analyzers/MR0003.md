# MR0003: A task, a result or an Error is stored as the value of a result

| Property | Value |
| -------- | ----- |
| **Rule ID** | MR0003 |
| **Title** | A task, a result or an Error is stored as the value of a result |
| **Category** | Usage |
| **Enabled by default** | As error; [not configurable](README.md#configuring-the-rules) |
| **Applicable languages** | C# |
| **Code fix** | No |

## Cause
The implicit conversion from a value to `Result<T>` is applied to a `Task`, a `Task<T>`, a `ValueTask`, a `ValueTask<T>`, a `Result`, a `Result<T>` or an `Error`. That happens when `T` is `object` or another base type of them.

## Rule description
A value of the type `T` converts to a successful `Result<T>`. A task and a result are an `object` too, so for a `Result<object>` the compiler accepts them as the value: `Result<object> result = SaveAsync();` is a successful result that holds the task, which nobody awaits, and a failed result stored this way is a success.

The same conversion applies to what a function returns: on a `Result<object>`, `Else(e => Validate(0))` replaces a failed result with a successful one that holds the `Result<int>` of `Validate`.

The rule does not report:

* the conversion from an `Error`, which gives a failed result (e.g., `Result<object> result = error;`);
* a value of any other type (e.g., `Result<object> result = "text";`);
* a type argument written as the type of the value, which stores it on purpose (e.g., `Result<Task<int>> result = GetAsync();`);
* `Result<T>.FromValue`, which stores the value on purpose (e.g., `Result<object>.FromValue(GetAsync())`).

## How to fix violations
* Await the task, and convert its value.
* Convert the value of the other result, not the result (e.g., `Validate(0).Then(x => (object)x)`).
* To store the task or the result on purpose, call `Result<T>.FromValue`, or write its type as the type argument (e.g., `Result<Task<int>>`).

## When to suppress warnings
Do not suppress this rule. A task or a result that is meant to be the value is stored with `Result<T>.FromValue` or as the value of a result whose type argument is its type, and is then not reported.

## Suppress a warning
The rule is reported as an error and is not configurable: `#pragma warning disable MR0003`, `<NoWarn>` in the project file and a severity in a configuration file have no effect, as for a compile error. See [Configuring the rules](README.md#configuring-the-rules) for what still silences it.

## Examples
### Violations
```csharp
Result<object> obj = Result<object>.FromValue(1);
Task<Result<object>> objTask = Task.FromResult(obj);
Task SaveAsync() => Task.CompletedTask;
Task LogAsync(Error e) => Task.CompletedTask;
Result<int> GetResultOfInt() => Result.FromValue(1);

// MR0003: a successful result that holds the task
Result<object> saved = SaveAsync();

// MR0003: a successful result that holds the Result<int>
Result<object> wrapped = GetResultOfInt();
var replaced = obj.Else(e => GetResultOfInt());

// MR0003: a failed result is replaced by a successful one that holds the task
var logged = objTask.ElseAsync(e => LogAsync(e));
```

### Fixes
```csharp
Result<object> obj = Result<object>.FromValue(1);
Task<Result<object>> objTask = Task.FromResult(obj);
Task<int> GetIntAsync() => Task.FromResult(5);
Task LogAsync(Error e) => Task.CompletedTask;
Result<int> GetResultOfInt() => Result.FromValue(1);
Error error = Error.Failure(ErrorUri.Tag("tag:exampleapp.com,2026:errors:operation:failed"), "The operation failed.");

Result<object> loaded = await GetIntAsync();

Result<object> converted = GetResultOfInt().Then(x => (object)x);
var replaced = obj.Else(e => GetResultOfInt().Then(x => (object)x));

// A side effect on a failed result: IfErrorAsync awaits the task
var logged = await objTask.IfErrorAsync(e => LogAsync(e));

// Not reported: an Error gives a failed result
Result<object> failed = error;

// Not reported: the task is stored on purpose
Result<object> stored = Result<object>.FromValue(GetIntAsync());
Result<Task<int>> kept = GetIntAsync();
```
